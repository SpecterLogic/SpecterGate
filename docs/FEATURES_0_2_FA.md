# راهنمای قابلیت‌های نسخهٔ ۰٫۲

این نسخه امکانات فهرست‌شده در بررسی قبلی را به پنل اضافه می‌کند. همهٔ قابلیت‌های همهٔ نسخه‌ها و انشعاب‌های پنل‌های دیگر را پوشش نمی‌دهد. فروش و پرداخت خودکار جزو پروژه نیست.

## هسته‌ها و پروتکل‌های جدید

در «اینباندها»، پروتکل و هسته را انتخاب کنید:

| پروتکل | هسته | تنظیم پیشنهادی |
| --- | --- | --- |
| VLESS، VMess، Trojan | Xray یا Sing-box | انتقال و TLS سازگار با کلاینت |
| Shadowsocks | Xray یا Sing-box | در Sing-box از AEAD-2022 استفاده می‌شود |
| Hysteria2 و TUIC | Sing-box | RAW و TLS با گواهی معتبر؛ پورت UDP باز باشد |
| ShadowTLS v3 | Sing-box | RAW، بدون TLS اضافی؛ دامنهٔ دست‌دهی در تنظیمات پیشرفته |
| SSH | SSH اختصاصی پنل | RAW، بدون TLS اضافی؛ نام کاربر و رمز مستقل حساب |
| MTProto | MTG | RAW، بدون TLS اضافی؛ انتخاب کاربر اختصاصی در تنظیمات پیشرفته |

پس از تنظیم دسترسی کاربر به اینباند، تنظیمات Xray و سپس Sing-box را اعمال کنید. هسته‌های جانبی از سرویس Xray برای حسابداری و مسیریابی استفاده می‌کنند؛ Xray باید فعال باشد. وضعیت سرویس‌ها و خطای راه‌اندازی در صفحهٔ اینباندها نمایش داده می‌شود.

هسته‌های جانبی فعلاً فقط روی نود محلی اجرا می‌شوند. برای هر ورودی MTProto یک کاربر و پورت عمومی مستقل تعیین کنید؛ پورت خصوصی relay آن نیز نباید با پورت دیگری تداخل داشته باشد. ساخت ورودی به‌تنهایی به کاربر محدودشده دسترسی نمی‌دهد؛ مجوز منابع را هم تنظیم کنید.

SSH حساب سیستم‌عامل ایجاد نمی‌کند و شل، اجرای فرمان و بازکردن پورت روی سرور ندارد. برای حفظ کلید میزبان، بک‌آپ رمزگذاری‌شدهٔ پنل را نگه دارید. ShadowTLS به خروجی کامل Sing-box نیاز دارد. XHTTP و mKCP را با هستهٔ Xray بسازید. گزینه‌های پیشرفتهٔ Xray را برای Sing-box فعال نکنید.

## رمزنگاری و پورت مشترک

- در تنظیمات پیشرفتهٔ اینباند Xray، تب «رمزنگاری VLESS» جفت کلید ML-KEM را می‌سازد. خروجی کامل Xray JSON را وارد کلاینت سازگار کنید.
- تب FinalMask ماسک‌های TCP و UDP را تنظیم می‌کند. UDP در این اتصال هسته برای mKCP است. دو طرف باید تنظیم یکسان داشته باشند؛ ماسک‌ها تضمین اتصال روی هر شبکه نیستند.
- در TLS کلید ECH و در Reality جفت کلید ML-DSA-65 قابل ساخت است. کلید خصوصی فقط در سرور می‌ماند. کلاینت باید نسخهٔ سازگار داشته باشد.
- برای fallback، یک ورودی VLESS/Trojan با RAW و TLS بسازید؛ مقصد را پورت یک سرویس یا اینباند داخلی روی `127.0.0.1` تعیین کنید. انتخاب مسیر با SNI، ALPN یا path انجام می‌شود. پورت مقصد نباید همان پورت ورودی باشد. ترکیب fallback و VLESS Encryption مجاز نیست.

گزینه‌های قدیمی آزمایشی ECH/FinalMask/XDRIVE به‌صورت پرچم صوری پذیرفته نمی‌شوند؛ از تب‌ها و کلیدهای واقعی بالا استفاده کنید. XDRIVE و OpenVPN در این نسخه پیاده‌سازی نشده‌اند.

## دستگاه، ریست حجم و تمدید

در فرم ساخت یا ویرایش کاربر:

1. «محدودیت HWID» تعداد شناسه‌های مجاز دریافت ساب را تعیین می‌کند. برنامه باید هدر `X-HWID` بفرستد؛ در غیر این صورت ساب محافظت‌شده تحویل داده نمی‌شود. فقط هش شناسه ذخیره می‌شود. این شناسه را خود برنامه می‌فرستد و احراز سخت‌افزاری غیرقابل جعل نیست.
2. در بخش دستگاه‌ها، ثبت دستگاه قدیمی را حذف کنید. کانفیگ دانلودشده با حذف این ثبت باطل نمی‌شود؛ برای ابطال، اطلاعات اتصال کاربر را بچرخانید.
3. «دورهٔ ریست حجم» بر حسب روز، مصرف را در فاصله‌های مشخص صفر می‌کند.
4. برای تمدید خودکار، روزهای تمدید و تعداد دفعات باقی‌مانده را مشخص کنید. هر تمدید یک نوبت کم می‌کند، زمان و مصرف را تازه می‌کند. پیش‌فرض تمدید خاموش است؛ پرداختی انجام نمی‌شود.

کارهای دوره‌ای بر اساس مدت سپری‌شده و زمان UTC اجرا می‌شوند، نه اول ماه تقویم شمسی. سقف IP آنلاین با HWID متفاوت است؛ حسابداری IP مستقیم Xray شامل تونل‌های جانبی و کاربران پشت NAT به‌عنوان دستگاه مستقل نمی‌شود.

## Cloudflare

در «یکپارچه‌سازی‌ها»، مالک می‌تواند Zone ID و API Token همان zone را وارد کند. توکن به مجوز خواندن Zone و ویرایش DNS نیاز دارد و رمزگذاری‌شده ذخیره می‌شود. از دادن مجوز کل حساب خودداری کنید.

رکورد A/AAAA را می‌توان ساخت یا تغییر داد. برای انتخاب IP لبه، اینباند TLS سازگار با CDN و رکورد پروکسی‌شده لازم است؛ وب‌سرور، گواهی و مسیر origin را از قبل درست کنید. تست دستی یا دوره‌ای از چند IP ثابت Cloudflare انجام می‌شود و فقط پس از پاسخ HTTPS معتبر، آدرس انتشار کانفیگ تغییر می‌کند. خطای تست، آخرین آدرس معتبر را حفظ می‌کند.

این اندازه‌گیری از سمت سرور است؛ کیفیت دسترسی مشترک روی شبکهٔ خودش را اثبات نمی‌کند. رکورد DNS واقعی در تست‌های محلی تغییر داده نشده است.

## اعلان‌ها

SMTP و Discord را در یکپارچه‌سازی‌ها تنظیم و فعال کنید. ایجاد حساب، تغییر وضعیت، ریست و تمدید در صف پایدار اعلان ثبت می‌شوند. ارسال ناموفق با فاصله و سقف تلاش تکرار می‌شود. در قطع ناگهانی پس از دریافت پیام توسط سرویس مقصد، امکان تکرار یک پیام وجود دارد. پیام‌رسانی واقعی به SMTP/Discord نیازمند تنظیمات نصب شماست. وظیفهٔ ربات تلگرام همان مدیریت مجاز کاربران و بک‌آپ مالک است.

## پایگاه داده

نصب‌کننده گزینه‌های `sqlite`، `postgresql`، `mysql`، `mariadb` و `timescaledb` را می‌پذیرد:

```bash
sudo bash /tmp/spectergate-install.sh --domain panel.example.com --database postgresql --private-panel
```

SQLite پیش‌فرض است. برای سرور جدید یکی از گزینه‌ها را انتخاب کنید؛ تغییر گزینه روی نصب موجود، مهاجرت خودکار داده بین دو موتور نیست. بستهٔ MySQL باید در توزیع شما موجود باشد؛ در Debian می‌توان MariaDB را انتخاب کرد. TimescaleDB به مخزن رسمی و بستهٔ سازگار سیستم نیاز دارد؛ افزونه فعال می‌شود ولی جدول‌های موجود خودکار به hypertable تبدیل نمی‌شوند.

برای Docker فایل override متناظر `docker-compose.mysql.yml`، `docker-compose.mariadb.yml` یا `docker-compose.timescale.yml` را همراه فایل اصلی استفاده کنید. رمز کاربر برنامه و مدیر دیتابیس را جدا و تصادفی تعیین کنید. بک‌آپ پنل شامل snapshot قابل بازیابی و dump بومی پایگاه داده است.

## به‌روزرسانی امضاشده

در نصب بومی جدید، سرویس مستقل root و timer نصب می‌شود. در یکپارچه‌سازی‌ها، مالک می‌تواند انتشار پایدار امضاشده را درخواست کند یا بررسی روزانه را فعال کند. به‌روزرسانی خودکار پیش‌فرض خاموش است و ابتدا باید رمز بک‌آپ تنظیم شود.

worker فقط تگ پایدار امضاشدهٔ مخزن رسمی را می‌پذیرد. نسخهٔ نامزد پیش از توقف سرویس ساخته و بک‌آپ رمزگذاری‌شده گرفته می‌شود. در خطای اعمال، بازگرداندن کد و باینری قبلی تلاش می‌شود؛ دیتابیس خودکار عقب‌گرد نمی‌کند. فایل بک‌آپ پیش از ارتقا را نگه دارید و فضای دیسک را کنترل کنید. نصب Docker از worker میزبان استفاده نمی‌کند و باید با Compose ارتقا یابد.

چرخهٔ کامل ارتقای یک سرور عمومی در این محیط محلی آزمایش نشده است. قبل از ارتقای نصب اصلی، روی نسخهٔ آزمایشی و با بک‌آپ قابل بازیابی امتحان کنید.

## زبان و نصب روی گوشی

انتخاب فارسی/English در ورود و بالای پنل موجود است؛ جهت صفحه هم عوض می‌شود. ترجمه‌ها داخل برنامه‌اند و برای ترجمهٔ داده‌های کاربران درخواست بیرونی فرستاده نمی‌شود.

روی HTTPS و مرورگر سازگار، پنل را با گزینهٔ نصب برنامه به صفحهٔ اصلی اضافه کنید. PWA اطلاعات حساب، ساب و API را آفلاین ذخیره نمی‌کند؛ برای کار با پنل اتصال لازم است.

## محدودهٔ تست

انتقال داده و حسابداری با باینری واقعی محلی برای Sing-box، SSH و مسیر اختصاصی MTProto بررسی می‌شود. ECH/ML-DSA با اعتبارسنجی بومی هسته، و fallback، FinalMask و VLESS Encryption با تست‌های جداگانه پوشش دارند. این نتایج جای تست اتصال عمومی تلگرام، صدور SSL، API واقعی Cloudflare، تحویل اعلان‌ها و کیفیت شبکهٔ کاربران را نمی‌گیرند. تست سازگاری موتورهای دیتابیس در workflow جداگانهٔ GitHub اجرا می‌شود.
